# Allowance prober OAuth refresh fix

The allowance prober now resolves each lane's bearer through Pi's credential transaction. This prevents its refresh from erasing another account's rotated credential and avoids submitting an obsolete refresh token after a cooperating Pi process updates the same account.

## Plan and boundaries

- Reuse Pi's installed `AuthStorage` and Pi AI's `createModels/getAuth` resolver with OAuth-only Anthropic aliases. Remove the prober's own refresh endpoint, client ID, credential snapshot, and whole-file writer. Keep usage polling, per-lane continuation, publication, local fallback, and backoff unchanged.
- Isolate Node-install-relative runtime loading and compatibility checks in one importable prober auth helper. The runtime must match the reviewed Pi 0.87.1 installation; unsupported or absent modules fail closed. Never fall back to an unlocked writer or ambient API keys.
- Keep OAuth exceptions out of logs and persisted credential-failure state. Only emit fixed, credential-free failure categories.
- Test ceiling: four load-bearing cases. (1) A cross-account interleaving preserves both rotations; (2) two same-account resolvers recheck under the lock, including a stale pre-lock read; (3) missing/invalid auth or runtime/refresh failures fail closed without leaking credentials and do not block other lanes; (4) if needed, the standalone process uses the pinned Node installation to resolve fresh credentials and publish a mocked usage observation. All tests use temporary stores and mocked transport, not live services.
- CI needs an explicit compatible Pi runtime, because this repository does not install Pi as a dependency. Tests must fail rather than skip when the runtime is missing.

The diagnosis in `tasks/discovery/oauth-refresh-race.md` describes the original code at `3334e55b716e49c053c834c98482350441885c53`. Its isolated reproduction remains evidence of the old defect, not an incident root-cause claim or a test of the corrected code.

## Implementation and validation

The prober now asks Pi's `createModels/getAuth` resolver for each lane's OAuth bearer (`scripts/allowance-prober-auth.mjs:19–40`, `scripts/allowance-prober.mjs:179–199`). Pi's `AuthStorage` performs the locked expiry recheck, refresh, and persistence; the helper also rejects incomplete stored OAuth fields before asking Pi to resolve the lane. The prober no longer stores a credential snapshot or makes an independent OAuth token request. A missing or incompatible installed runtime records a fixed failure for each lane and sends no usage request. A missing credential or refresh error affects only its lane; raw OAuth exceptions and response bodies never enter the log or credential-failure file. Existing backoff, local usage, and authority publication paths remain in the prober. A generic request error also replaces the prior unbounded `error.message` in usage/publication logs.

`createAllowanceAuth` loads the Pi 0.87.1 package and its paired Pi AI modules relative to `process.execPath`. It verifies names, exact versions, and the required APIs before constructing OAuth-only alias providers. Pi AI's Anthropic OAuth module is a private file, so the explicit version gate prevents an unreviewed upgrade from silently changing refresh semantics. CI installs the matching Pi package globally under its selected Node runtime before running the tests (`.github/workflows/ci.yml:24`); an absent runtime fails the test file at import time. No runtime dependency was added to this package.

Four isolated regression tests were added in `test/allowance-prober-auth.test.mjs`. They cover (1) cross-account lost-update interleaving against a real Pi lock and store, (2) same-account stale reads and deduplicated rotation, (3) missing/wrong-type/incomplete auth, rejected refresh, and missing runtime without leaked error bodies, and (4) the standalone prober using its Node installation, mocked OAuth/usage transport, local usage writes, and lane continuation. Transport is denied unless mocked; the standalone child uses a temporary `HOME`, disables Keychain execution, bypasses authority publication, and touches only synthetic credentials. The fourth test also checks that failure state and stdout contain no synthetic secret or response body.

Validation: `node --test test/allowance-prober-auth.test.mjs` passed 4/4, no skips. `npm test` passed 34/34, no skips. `git diff --check` passed. The GitHub-hosted Node 22 and 24 CI jobs were not run locally. At source validation, neither the installed prober nor a running service was changed or exercised. The operator subsequently approved installation and live verification; the rollout is recorded below. After any Pi upgrade, review the private module paths and lock/refresh behavior, update the compatibility gate and CI pin together, and run the isolated tests before rollout. The historical reproduction now extracts the original source with `git show 3334e55b716e49c053c834c98482350441885c53:scripts/allowance-prober.mjs`; its incident-causation uncertainty remains unchanged.
